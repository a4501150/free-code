# CLAUDE.md

Only facts that cause an error or a silent bug when missed belong here.
Everything else must be inferable from the code; file-local gotchas are
commented IN the file that governs them.

## Build and test traps

- `bun run build` → `./cli`; `bun run dev` runs `src/` uncompiled. All shipped subsystems compile in unconditionally; the 4 opt-in flags (`--feature=NAME` on the build script) are in README.md — unknown names are silently ignored, so a typo becomes a dead flag.
- `bun run test` runs unit + e2e but does NOT typecheck or format; run `bun run typecheck`, `bun run test:unit`, `bun run format` yourself.
- e2e drives the COMPILED binary: run `bun run build:dev:full` first or you are testing stale code. Each e2e test gets `env -i` + temp HOME and asserts via the mock provider's request log, not the tmux pane.
- Unit tests share one process: `mock.module` and module-level `memoize` leak across files.
- The binary is not self-contained: `vendor/ripgrep/`, `vendor/search-tools/`, `vendor/agent-browser/` sidecars must move with it; system `rg` wins unless `USE_BUILTIN_RIPGREP=1`. `vendor/agent-browser/` is auto-registered at lowest precedence — a manual `agent-browser` config entry replaces it.
- `src/webui/generated/assets.ts` is git-ignored and regenerated by every build — never commit it.

## Prompt cache invariants

- Cache prefix order is `tools`, `system`, `messages`; the system prompt must stay byte-identical across sessions AND byte-stable for a session's lifetime: no `DANGEROUS_uncachedSystemPromptSection` may return (they were removed — re-adding one churns the single cached system block every turn). Session facts ride the domain-scoped persisted `user_context_snapshot`/`user_context_delta` (`memories`, `system`, `env`); mid-session-dynamic content rides its own attachment type (`mcp_tools_delta`, `mcp_instructions_delta`, `session_guidance`) — never the prompt.
- Dynamic carriers use the stateless-scan pattern: diff against announcements found in the transcript, and "no prior announcement" must mean a FULL announce, never silence — session start, post-compaction re-arm (`compact.ts`) and the subagent turn-0 seeds (`runAgent.ts`) all rely on it. `user_context_snapshot`/`delta` read from pre-domain transcripts carry no `domain` and must be treated as covering every domain (replay once, never re-baseline) or resume silently re-sends the whole context. Subagent MCP instructions ride the turn-0 attachment only — a system-prompt append duplicates the announce the agent's own pipeline emits.
- Everything inside the prefix must be byte-stable across builds too: tool descriptions (they embed the tool list) and the catalog manifest path. Tool-derived variation is free; global cache scope was dropped deliberately.
- The Edit tool description is the only place telling the model which Bash/Grep channels count as file sightings — keep it in sync with the allowlist in `src/utils/fileSightings.ts`.
- Attachments re-run per tool-loop iteration and stay in the conversation: a stable predicate duplicates on every tool call; standing policy belongs in the cached prefix. Once-per-window guards must inspect the transcript (compaction re-arms them). Count human turns or `message.id`s, never `AssistantMessage` objects (streaming emits one per content block).
- Mid-loop-injected attachments (memory-prefetch `relevant_memories`, plan_mode, diagnostics, …) are one-shot: appended after the tool_result block and replayed byte-identically in every later request — they never vanish from the live chain (query.ts recurses with them in `toolResults`). `isLoggableMessage` persists everything the model saw, so a resumed transcript has no holes: the only dropped type is `progress` (volume rationale, never sent to the model). A future type may be dropped from BOTH the next request and the transcript only by listing it in `EPHEMERAL_ATTACHMENT_TYPES` (`src/utils/sessionStorage.ts`) — persistence mirrors what-was-sent, and there are no such types today.
- The request `tools[]` block is frozen per session by the exposure filter (`isToolExposedToModel` in `src/services/api/claude.ts`): the mid-loop `refreshTools()` swap churns the in-memory pool for dispatch but cannot churn the cache prefix. What DOES churn `tools[]`: `alwaysLoad` servers connecting/disconnecting, blanket-deny rules added mid-session against an exposed tool, and coordinator-mode toggles.
- Wire features are adapter-owned: core sends provider-neutral intent (`RequestFeatureIntent`) and the Anthropic-family adapters derive beta headers, the body-beta list and the sticky fast-mode/AFK latches (`src/services/api/adapters/anthropicFeatures.ts`). Cache-break attribution asks the adapter for its cache-relevant feature descriptor — core-side beta/overage/fast-mode fields would mislabel non-Anthropic providers.
- The 1h-cache-TTL decision is a session fact persisted as the `cache-ttl-1h` transcript entry and adopted on resume (`restoreSessionMetadata`), never recomputed: `currentLimits` loads asynchronously, so a re-computed tier after resume is a different byte-prefix cache key.

## Silent-failure constraints

- Tool results are validated against `outputSchema` before rendering; a schema narrower than what `call()` returns silently removes the row. MCP output schemas must admit content arrays as well as strings.
- Reasoning continuation is provider-specific: a `ProviderType` missing from the predicate table loses all reasoning silently. Provider type does not imply auth method — Bedrock and Gemini acquire credentials themselves; Anthropic-only metadata, identity headers and signing stay behind the Anthropic-type gate.
- A `stream_event` leaving `src/services/api/claude.ts` carries domain types: extended thinking is `reasoning`, not `thinking`; use `src/types/domainGuards.ts` — raw `content_block` comparisons typecheck and silently never match.
- OpenAI-compatible adapters present every tool schema strict-shaped without setting `strict` (`src/services/api/adapters/strictPresentedSchema.ts`); `$ref` schemas go unmodified. Input null-stripping (`src/services/tools/toolExecution.ts`) removes only placeholder nulls — never one the schema admits.
- Sessions are shared: session IDs are not exclusive and live-holder checks fail open deliberately (`src/utils/concurrentSessions.ts`).
- Incremental sidechain writes must take their `startingParentUuid` from what actually persisted, not from the in-memory message list: a parent hint pointing at a message that never hit the transcript truncates the chain on load and silently blanks the drill-down's prompt + seed rows.
- Every hook path re-checks workspace trust; disabling all hooks must gate settings-, plugin- and session-derived hooks separately.

## Bash security

One parser, no fallback: `too-complex` must prompt. `shell-quote` is
display/completion only; wrapper resolution (`src/utils/bash/wrappers.ts`)
fails closed. `sourceText` excludes redirects — checking it alone misses
`> /tmp/evil`. A false-positive `isReadOnly` executes unprompted (it feeds
memory extraction and speculation auto-approval).

## Settings split

Provider keys ONLY in `~/.freecode/modelSettings.json` (the full key set is
`src/utils/settings/modelSettingsKeys.ts`); unknown keys are dropped
pre-validation. Everything else in `freecode.json`. Config home is
`~/.freecode` (`FREECODE_CONFIG_DIR`, fallback `CLAUDE_CONFIG_DIR`).
Behavior is configured through settings files, not env: the only
`CLAUDE_*`/`ANTHROPIC_*` names `src/` and `scripts/` may read from
`process.env` are the three buckets in `src/utils/envAllowlist.ts`
(auth, process/host mechanics, debug) — a unit test scans read sites and
fails on anything else. `settings.env` survives as child-process
passthrough; adding a behavior switch read from env requires allowlisting
it there.

## Terminal renderer

`src/ink.ts`. Scroll-follow rules are commented in
`src/ink/components/ScrollBox.tsx` and `src/components/FullscreenLayout.tsx`.
