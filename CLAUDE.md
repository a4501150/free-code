## Daily commands and build traps

- `bun run build` → `./cli` (10 flags); `bun run build:dev:full` → `./cli-dev` (dev-full set, incl. `WEBUI`). `--compile` is a misnomer: every build runs `bun build --compile`; the flag only relocates output to `dist/`. Feature names are not validated and unknown args are ignored — typos become dead flags. [FEATURES.md](FEATURES.md) is the sole authority per flag; [scripts/build.ts](scripts/build.ts) per behavior.
- `bun run dev` runs `src/entrypoints/cli.tsx` with NONE of the default feature defines. Build to test anything a flag gates.
- The binary is not self-contained: `vendor/ripgrep/` and `vendor/search-tools/` sidecars must move with it; system `rg` wins unless `USE_BUILTIN_RIPGREP=1`. `src/webui/generated/assets.ts` is git-ignored (stubbed when `WEBUI` off) — never commit it.
- `bun run test` neither typechecks nor formats; run `typecheck`, `test:unit`, `format` yourself. e2e drives the COMPILED `./cli-dev` in tmux (`build:dev:full` first — a stale build tests old code); each test gets `env -i` + temp HOME, asserts via the mock provider's request log, not the pane. Unit tests share one process: `mock.module` and module-level `memoize` leak across files.

## Cross-cutting rules

- Prompt cache prefix order is `tools`, `system`, `messages`; the static system prompt stays byte-identical across sessions (session facts ride the persisted `user_context_snapshot`), and everything inside the prefix — output-style bodies, tool descriptions, the catalog manifest path (via env-context attachment) — must be byte-stable. Tool-derived variation is free; global cache scope was dropped deliberately.
- Attachments re-run per tool-loop iteration and stay in the conversation: a stable predicate duplicates on every tool call; standing policy belongs in the cached prefix. Once-per-window guards must inspect the transcript (compaction re-arms them). Count human turns or `message.id`s, never `AssistantMessage` objects (streaming emits one per content block).
- OpenAI-compatible adapters present every tool schema strict-shaped without setting `strict` ([src/services/api/adapters/strictPresentedSchema.ts](src/services/api/adapters/strictPresentedSchema.ts)); `$ref` schemas go unmodified. Input null-stripping ([src/services/tools/toolExecution.ts](src/services/tools/toolExecution.ts)) removes only placeholder nulls — never one the schema admits.
- The Edit tool description is the only place telling the model which Bash/Grep channels count as file sightings — keep it in sync with the [fileSightings.ts](src/utils/fileSightings.ts) allowlist.
- Provider type does not imply auth method: Bedrock and Gemini acquire credentials themselves; Anthropic-only metadata, identity headers and signing stay behind the Anthropic-type gate. Reasoning continuation is provider-specific and not portable: a `ProviderType` missing from the predicate table loses all reasoning silently (`vertex`/`foundry` intentionally alias `anthropic`).
- A `stream_event` leaving [src/services/api/claude.ts](src/services/api/claude.ts) carries domain types: extended thinking is `reasoning`, not `thinking`; use [src/types/domainGuards.ts](src/types/domainGuards.ts) — raw `content_block` comparisons typecheck and silently never match.
- Bash security has one parser and no fallback: `too-complex` must prompt; `shell-quote` is display/completion only; wrapper resolution ([src/utils/bash/wrappers.ts](src/utils/bash/wrappers.ts)) fails closed. `sourceText` excludes redirects — checking it alone misses `> /tmp/evil`. `isReadOnly` feeds auto-approval consumers (memory extraction, speculation): a false positive executes unprompted.
- Tool results are validated against `outputSchema` before rendering; a schema narrower than `call()` output silently removes the row (MCP output must admit content arrays as well as strings).
