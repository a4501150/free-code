# AGENTS.md

This file provides guidance to AI coding agents (including Claude Code) when working with code in this repository.

`CLAUDE.md` is a symlink to this file — edit here, never replace the symlink.

Only facts that cause an error or a silent bug when missed belong here.
Everything else must be inferable from the code; file-local gotchas are
commented IN the file that governs them.

## Build and test traps

- `bun run build` → `./cli`; `bun run dev` runs `src/` uncompiled. Opt-in build flags are in README.md — unknown names are silently ignored, so a typo becomes a dead flag.
- `bun run test` runs unit + e2e but does NOT typecheck or format; run `bun run verify` for the full gate (typecheck + format check + unit + e2e). Single test file: `bun test tests/unit/<name>.test.ts`.
- e2e drives the COMPILED binary: run `bun run build:dev:full` first or you are testing stale code. Each e2e test gets `env -i` + temp HOME and asserts via the mock provider's request log, not the tmux pane. An overdrawn mock queue answers 400 (never 500 — the SDK's 5xx retry backoff turns a fixture gap into a minutes-long hang), and timeout messages embed the request log; agent-loop fixtures must provision the subagent's explicit EndTurn turn.
- tmux e2e `waitFor` budgets scale with machine load (up to 3x, `loadScaledTimeoutMs`), so boot/dialog-paint waits stretch instead of flaking on a busy box. Rerun failed files in isolation before bisecting — cross-run session-registry holders and paint races still move between runs.
- Unit tests share one process: `mock.module` and module-level `memoize` leak across files.
- The binary is not self-contained: `vendor/` sidecars must move with it. System `rg` wins unless `USE_BUILTIN_RIPGREP=1`; `vendor/agent-browser/` registers at lowest precedence (a manual config entry replaces it).
- `src/webui/generated/assets.ts` is git-ignored and regenerated by every build — never commit it.

## Prompt cache invariants

- Prefix order is tools, system, messages. The system prompt must stay byte-identical across sessions and byte-stable for a session's lifetime — do not reintroduce an uncached system-prompt section (the old `DANGEROUS_uncachedSystemPromptSection` churned the single cached block every turn). Session facts ride the persisted `user_context_snapshot`/`user_context_delta`; mid-session-dynamic content rides its own attachment type (`deferred_tools_delta`, `mcp_instructions_delta`, `mcp_tools_delta`, `session_guidance`) — never the prompt.
- Dynamic carriers use the stateless-scan pattern: diff against announcements found in the transcript, and "no prior announcement" must mean a FULL announce (session start, post-compaction re-arm, subagent turn-0), never silence. A snapshot/delta carrying no `domain` covers every domain: replay once, never re-baseline.
- Everything inside the prefix must be byte-stable across builds too: tool descriptions (they embed the tool list). Catalog declarations-file paths ride the `deferred_tools_delta`/`mcp_tools_delta` announcements, not the prompt (the old `tool_catalog` pointer carrier was redundant with them and is in `LEGACY_ATTACHMENT_TYPES`).
- The Edit tool description is the only place telling the model which Bash channels count as file sightings — keep it in sync with the allowlist in `src/utils/fileSightings.ts`.
- Attachments re-run per tool-loop iteration and stay in the conversation: a stable predicate duplicates on every tool call; once-per-window guards must inspect the transcript (compaction re-arms them); count human turns or `message.id`s, never `AssistantMessage` objects (streaming emits one per content block).
- Wire features are adapter-owned: core sends provider-neutral `RequestFeatureIntent`; Anthropic-family adapters derive beta headers and sticky latches (`src/services/api/adapters/anthropicFeatures.ts`). Cache-break attribution must use the adapter's descriptor, never core-side fields.

## Silent-failure constraints

- Tool results are validated against `outputSchema` before rendering; a schema narrower than what `call()` returns silently removes the row — MCP output schemas must admit content arrays as well as strings.
- Reasoning continuation is a per-`ProviderType` predicate table: a missing type loses all reasoning silently. Provider type does not imply auth method — Anthropic-only metadata, identity headers and signing stay behind the Anthropic-type gate.
- A `stream_event` leaving `src/services/api/claude.ts` carries domain types: extended thinking is `reasoning`, not `thinking`; use `src/types/domainGuards.ts` — raw `content_block` comparisons typecheck and silently never match.
- Sessions are shared and live-holder checks fail open deliberately (`src/utils/concurrentSessions.ts`). SendMessage `session:<id>` needs that registry entry plus the target's attach socket; no descriptor ⇒ "not addressable".
- Backgrounded agent `output_file` is the agent's full JSONL transcript — the parent must never Read it; completion notifications are the only retrieval channel. Background SHELL output files are plain text and safe to Read.
- Incremental sidechain writes must take their `startingParentUuid` from what actually persisted, not the in-memory message list: a hint pointing at an unpersisted message truncates the chain and silently blanks the drill-down.
- QueryEngine's slash-command `setMessages` must preserve the caller's array identity (splice in place, never assign a fresh array): the print loop, the attach runtime's `getMessages()` and the next `ask()` all hold `config.initialMessages` by reference, and a headless `/clear` that swaps the array silently clears nothing — the WebUI keeps publishing the pre-clear conversation.
- Every hook path re-checks workspace trust; disabling all hooks must gate settings-, plugin- and session-derived hooks separately.
- Task lists rebuild from the transcript on resume (`src/utils/taskListRebuild.ts`): the scan must read the raw JSONL — the resume-loaded in-memory chain stops at the compact boundary — and must never seed an override/tasks-mode list (`--tasks` pins its queue via `setTaskListIdOverride`, and that queue holds cross-process state no transcript contains). Rebuild is skipped whenever the target list already has files on disk (crash leftover or a concurrent resumer seeded it — disk wins).

- RunCode evaluates model-authored TS with `Bun.Transpiler` `transformSync` + `AsyncFunction` — disk-path `import()` does not exist in the compiled binary, and the `transpile`/`transpileAsync` method names do not exist in our Bun version. The catalog `.ts` files are documentation only: the loader builds runtime namespaces from the live pool with `catalogExportName` (writer). If docs and loader identifier rules drift, script imports fail with confusing "no export" errors.
- RunCode's `outputSchema` and the bridge's segment builder are a lockstep pair — a schema narrower than what `call()` returns silently drops segments (same failure mode as MCP output schemas).
- The tool-catalog state files are harness-owned and must never be named in prompts; the model-facing catalog is exactly `servers/*.ts` + `builtins.ts`. Project-scope servers (`'project'`/`'local'` config) render into a project-keyed dir `<config-home>/tool-catalog/projects/<key>/` (state: sibling `<key>.json`); everything else plus built-ins stays in `<config-home>/tool-catalog/` (state: `tool-catalog.json`). Catalog dirs are shared across concurrent sessions, so writes are additive: the manifest is a union of the previous manifest and the session's render, a session never deletes a server file it doesn't render, and reaping happens only via 30-day age GC for unclaimed entries. Announces (`mcp_tools_delta`) intersect with the live pool — RunCode dispatch would fail for a server whose file exists but isn't connected.

## Bash security

One parser, no fallback: `too-complex` must prompt. `shell-quote` is display/completion only; wrapper resolution (`src/utils/bash/wrappers.ts`) fails closed. `sourceText` excludes redirects — checking it alone misses `> /tmp/evil`. A false-positive `isReadOnly` executes unprompted (it feeds memory extraction and speculation auto-approval).

The bash provider's prefix chain enables `pipefail` (`src/utils/shell/bashProvider.ts`): a piped command reports the failing component's exit, so `verify | tail` cannot return 0 over a failed verify. `| head`-style truncation can therefore surface exit 141 (SIGPIPE) for commands that produced the output the model wanted — expected, not a failure.

Bash output capture composes two fail-closed rewrites (`src/utils/bash/outputCapture.ts`): `>`/`>>` targets are redirected to the harness output file, and a strict trailing `| tail`/`| head` stage is STRIPPED before exec — executing it would truncate the stream before capture (the user's Shell-details view reads the same file, and a piped `tail` buffers until EOF so the live view shows nothing). The model's inline stdout is HEAD-capped (`getStdout`, ~30k), never tail-capped: the last lines a stripped `tail` would have delivered are not reconstructable from stdout — over the cap the result delivers preview + file path + exit code instead.

## Settings split

Provider keys ONLY in `~/.freecode/modelSettings.json` (full key set: `src/utils/settings/modelSettingsKeys.ts`); unknown keys are dropped pre-validation. Everything else in `freecode.json`. Config home is `~/.freecode` (`FREECODE_CONFIG_DIR`, fallback `CLAUDE_CONFIG_DIR`). Project settings load only from `<cwd>/.freecode/freecode.json` (a legacy `<cwd>/.claude/freecode.json` is not read); local overrides from `<cwd>/.freecode/freecode.local.json`. Behavior is configured through settings files, not env: the env reads `src/` and `scripts/` may perform are allowlisted in `src/utils/envAllowlist.ts` (enforced by a unit test that names the file).

## Assistant mode — conversation persistence gotchas

- In assistant mode (gateway-spawned headless child rooted at `~/.freecode/webui/assistant`), `/clear` truncates the session transcript JSONL IN PLACE and keeps the same session id — unlike normal sessions, where `/clear` regenerates the id and starts a new append-only transcript. The gateway resume pointer at `~/.freecode/webui/assistant-session.json` references the session id, so keeping the id keeps the pointer valid across restarts; a stale id pointing at a surviving pre-clear transcript would resurrect the cleared conversation.
- The resume pointer is rewritten opportunistically (on `session_changed` events, `/api/sessions` and assistantStatus descriptor re-reads, and at gateway shutdown via the attach descriptor's live id), not only at shutdown. Edge case: restarting the gateway strictly between `/clear` and the first persisted post-clear message makes `--resume` find a messages-zero transcript; the bootstrap then falls back to a fresh chat with a NEW id and the truncated file is orphaned — graceful, accepted behavior.

## WebUI client gotchas

- The embedded client bundle must stay small: heavy renderers are lazy-loaded from a pinned jsdelivr URL via `import()` of a `string`-typed variable (Bun inlines literal-specifier dynamic imports and bakes a URL that `source="bundled"` blocks; the loader-shell path must also stay inside `dist/` or mermaid's sibling-chunk fetches 404). CSP allows that origin in `script-src`; `style-src` carries `'unsafe-inline'` solely for the `<style>` block inside mermaid's SVG.
- `tests/unit/` has no React/browser environment: client UI code is tested from `tests/e2e/` with the real gateway (SSE shape: `/stream` emits bare `data: {json}` frames — the `event:` line is client-side replay-only).
